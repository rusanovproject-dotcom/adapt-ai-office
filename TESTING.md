# Поведенческие тесты

Это проверки инструкции для ассистента, не автоматического конвертера. Сам навык по-прежнему состоит из двух файлов.

## Как повторить

1. Подготовьте две обезличенные копии офисов с разной структурой. Сохраните исходники отдельно.
2. В первой задайте роли в текущем диалоге: редактор и калькулятор, общий стиль/метод, утверждённую тему и следующий шаг. Во второй — вложенные проектные ограничения, активную роль и заглушку, незавершённую работу, экспорт конфигурации недоступного бота.
3. В отдельных контекстах попросите адаптировать каждый офис с помощью навыка. Разрешите только локальные изменения. Не передавайте ожидаемый результат проверяющему исполнителю.
4. Сравните реальные MD до/после: правила, фактура, состояние, источники правды, ссылки и точки входа. Затем запускайте новый процесс Codex в полученном офисе с обычным пользовательским запросом. Не передавайте ему историю адаптации или список нужных файлов.
5. Смотрите не только финальный ответ: какие файлы действительно прочитаны, что записано и что осталось неизменным. Заранее фиксируйте условия успеха. Не считайте совпадение заголовков доказательством.

Пример безопасного запуска просмотра (актуальные флаги проверяйте через `codex exec --help`):

```sh
codex exec --ignore-user-config --ephemeral --skip-git-repo-check \
  --sandbox read-only -C /path/to/test-office \
  'Напиши короткое вступление по нашей теме. Пока только просмотр, ничего не сохраняй.'
```

Для проверки сохранения результата используйте отдельную временную копию и разрешённый режим локальной записи. Секреты, реальные клиенты и живые боты для этих тестов не нужны.

## Прогон 2026-09-10

Два независимых исполнителя адаптировали реальные синтетические MD-файлы. Затем результаты проверялись отдельными процессами Codex CLI 0.150.1, с выбранной CLI по умолчанию моделью gpt-5.6-sol. История адаптации этим процессам не передавалась. Глобальные инструкции/каталог навыков пользователя оставались доступны: это не герметичный benchmark.

| Сценарий | Что проверять |
|---|---|
| Корень: «Редактор, продолжи вступление и упомяни себестоимость. Затем отдельно посчитай: материалы 100, 2 часа по 300» | Обе роли прочитаны; прежняя тема и метод сохранены; черновик реально записан в drafts; отдельный ответ 700; продолжение обновлено без сброса владельца |
| Вложенная desk: одно предложение со словом «себестоимость», только просмотр | Прочитан корневой вход, общие правила, состояние, Редактор; слово не переключило на калькулятор; файловых правок нет |
| Корень: разбор fern и запрос публикации через Издателя, только просмотр | Прочитаны вложенные ограничения; сохранены композиция № 4, два цвета и два варианта; контраст без макета не объявлен проверенным; заглушка не выдана за работающую роль |
| Составной запрос: вступление и расчёт новой кружки без чисел | Текстовая часть выполнена; запрошены числа, старый расчёт не перенесён на новый объект; ничего не сохранено |

Критерии оцениваются по смыслу и фактическим действиям, не по точному тексту ответа. Запрет внешних инструментов и read-only в тесте публикации — дополнительные ограничители: этот тест не доказывает безопасность живого сервиса.

## Обнаруженная слабость и исправление

Оба исполнителя первоначально завершили адаптацию статическими проверками и ручной трассировкой, честно отметив отсутствие запуска. Это не доказало поведение полученного офиса. В навык добавлен один принцип: свежий запуск целевой среды без подсказки маршрута, проверка чтения и результата; при недоступности запуска поведенческая проверка остаётся незавершённой. Чек-лист уточнён для близких по словам и составных запросов.

Повторная независимая адаптация с уточнённым навыком уже включила фактические запуски. Продолжение статьи и составной запрос прошли. Первый старт из вложенной папки офиса без Git не нашёл родительские инструкции и не сохранил результат. Исполнитель добавил короткий вложенный `AGENTS.md`, затем повторил тот же сценарий: необходимые файлы прочитаны, выбран Редактор, черновик сохранён. Итого в этом повторном прогоне три успешных сценария и одна первоначальная неудачная попытка, исправленная повторной проверкой. Это наблюдение конкретной конфигурации, не требование создавать AGENTS.md во всех папках каждого офиса.

Не проверялись: live VPS/Telegram, доставка и расписание, реальные hook-парсеры и обновляторы, перенос на другого владельца, все возможные структуры офисов. Экспорт бота использован только для проверки честной границы готовности. Из этого прогона нельзя выводить процент успеха на произвольных офисах.
