# Adapt AI Office

**Перенос AI-офиса между Claude Code и Codex — с сохранением его поведения, памяти и подключённых автоматизаций.**

Навык для AI-ассистента: обследует существующий офис, строит план адаптации и ведёт выполнение по проверяемым этапам. Подходит для смены владельца/направления, перехода между runtime и совместной работы в двух средах.

Если к офису уже подключены Telegram-боты, cron или серверные процессы, они входят в общую карту переноса. Навык помогает выяснить, какой процесс реально вызывает модель, где хранится состояние и как проверить результат после переключения.

> Это набор инструкций и проверочных сценариев для ассистента, а не готовый CLI-конвертер или движок Telegram-ботов. Работоспособность конкретной миграции проверяется в её целевом окружении.

## Что умеет

- **Инвентаризация:** инструкции, агенты и персоны, skills, ссылки, память, хуки, инструменты, серверы и расписания.
- **План переноса:** точные пути, зависимости, владельцы изменений, проверки, checkpoints и rollback.
- **Файлы и маршруты:** custom metadata, вложенные правила, рабочая директория, незавершённый onboarding, заглушки агентов и обновления шаблона.
- **Сервер и Telegram:** runner/provider, service user, авторизация, сессии, единственный consumer, расписания и подтверждение доставки.
- **Проверка:** обнаружение зависимостей, реальный результат, повторный запуск без дублей, сохранность состояния и явные непроверенные ветви.

## Установка

Скачайте репозиторий:

```bash
git clone https://github.com/rusanovproject-dotcom/adapt-ai-office.git
```

Из каталога **вашего офиса** скопируйте только папку навыка в выбранную среду. Если одноимённый навык уже существует, сначала сравните версии; не накладывайте их друг на друга.

### Codex

```bash
mkdir -p .agents/skills
cp -R /path/to/adapt-ai-office/skills/adapt-ai-office .agents/skills/
```

### Claude Code

```bash
mkdir -p .claude/skills
cp -R /path/to/adapt-ai-office/skills/adapt-ai-office .claude/skills/
```

Замените `/path/to/adapt-ai-office` на путь к скачанному репозиторию и откройте новую сессию в офисе. Проверьте, что ассистент находит навык `adapt-ai-office`. Копируется весь каталог: главная инструкция использует references, assets и fixtures.

Не устанавливайте весь репозиторий вместе с историей тестовых запусков как набор skills. В этом репозитории публикуется одна актуальная версия навыка.

## Примеры запросов

```text
Используй adapt-ai-office. Перенеси мой существующий офис с Claude Code
на Codex. Владелец тот же. Сначала обследуй файлы и зависимости,
затем составь план и подготовь локальный кандидат.
```

```text
Адаптируй эту болванку офиса под консультанта и Codex.
Сохрани полезные рабочие сценарии, выясни, какие роли действительно нужны.
```

```text
Перенеси весь офис на Codex, включая существующего Telegram-бота
и ежедневную сводку на сервере. Если доступа к серверу нет,
отметь непроверенную ветвь и подготовь конкретный план её проверки.
```

```text
Продолжи адаптацию по checkpoint. Локальный staging уже разрешён.
Проверь изменения исходных файлов и не повторяй неизвестную отправку.
```

## Как проходит работа

1. Обследование и карта зависимостей.
2. Согласованный объём адаптации и план этапов.
3. Пробный перенос одного рабочего сценария.
4. Изменения волнами, проверки и сохранение checkpoint.
5. Применение в пределах выданного разрешения и наблюдение за результатом.

Основные результаты: `adaptation-report.md`, `adaptation-plan.md`, `verification-report.md`, `handoff.md`. Подробные реестры добавляются по необходимости.

Навык сохраняет ранее выданное разрешение на работу. Публикация, production switching и другие внешние изменения должны входить в разрешённый пользователем объём. Персональные данные и секреты не копируются в переносимый пакет.

## Где граница

Отдельная установка Codex, обычная уборка файлов, создание нового бота или смена движка одного бота без адаптации офиса относятся к другим задачам. Навык не требует конкретного состава команды, структуры `team/` или определённого серверного движка.
